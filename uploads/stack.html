01 The Mental Model — What ARE these structures?

Before writing a single line of code, you need to feel what a stack and a queue are. Once you feel them, you'll see them everywhere.

The Stack — Last In, First Out (LIFO)

Imagine a stack of plates on a table. You put a plate on top. You take from the top. You never reach into the middle. The last plate you put down is the first one you pick up.

🔑 Core Insight

A stack is useful whenever the most recent thing matters most, or whenever you need to undo/reverse something. Think: browser back button, function call stack, parenthesis matching.

Real-world stacks you already use without knowing:

void funcA() { funcB(); } // funcA is on the call stack void funcB() { funcC(); } // funcB pushed ON TOP of funcA void funcC() { ... } // funcC pushed ON TOP of funcB // Return order: funcC → funcB → funcA (LIFO!)

The Queue — First In, First Out (FIFO)

Imagine people standing in line at a ticket counter. The first person who arrived gets served first. New arrivals join at the back. Nobody cuts in line.

🔑 Core Insight

A queue is useful when you need to process things in the order they arrived. Think: BFS traversal, print queues, task scheduling, sliding windows.

When to immediately think "Stack" vs "Queue"?

🥞 Stack Triggers

You see these words/patterns in the problem:

matching pairs nested structure undo operation previous greater/smaller evaluate expression next greater element monotone histogram

🚶 Queue Triggers

You see these words/patterns in the problem:

level order BFS / shortest path sliding window process in order k elements at a time first occurrence scheduling rotting / spreading

Why does this matter for competitive programming?

In CP, you rarely get told "use a stack". You get a problem like "find the maximum of all subarrays of size k" or "find the sum of minimums of all subarrays". Your job is to recognize the underlying pattern. This guide is about building that pattern recognition.

02 The 8 Core Patterns

Every stack/queue problem you'll ever see fits into one (or a combination) of these patterns. Learn these, and you'll be able to tackle any problem.

Pattern 1: Matching / Balancing

Recognize it: The problem involves pairs — parentheses, brackets, braces, tags. You need to check they are correctly nested or find unmatched ones.

Core idea: Push opening symbols. When you see a closing symbol, check if it matches the top of the stack and pop.

Pattern 2: Monotonic Stack (KING of hard problems)

Recognize it: Questions about next greater element, previous smaller element, largest rectangle, trapped water, subarray min/max. Anything where for each element you want to quickly find the nearest element that is greater or smaller.

Core idea: Maintain a stack where elements are always in sorted order (either always increasing or always decreasing). When an element breaks the monotonicity, elements are popped — and the moment of popping gives you the answer for the popped element.

⚡ This is the most important pattern

Almost every LeetCode Hard stack problem and every 1600+ CF stack problem uses a monotonic stack. Master this pattern first.

Pattern 3: Stack for Expression Evaluation

Recognize it: Evaluate mathematical or logical expressions. Operators and operands. Possibly with parentheses.

Core idea: Use two stacks — one for numbers, one for operators. When you see a closing paren or a lower-precedence operator, pop and evaluate.

Pattern 4: Simulation / State Machine with Stack

Recognize it: You're simulating a process where events happen and cancel each other — asteroids colliding, undo operations, nested directories.

Core idea: The stack represents the current state. Each element decides whether to cancel/modify the top of the stack or get pushed.

Pattern 5: Monotonic Queue (Deque)

Recognize it: Sliding window maximum/minimum. You have a window of size k moving over an array and you need the max or min in O(1) per step.

Core idea: Use a deque. Maintain elements in decreasing order (for max) or increasing order (for min). Elements outside the window get removed from the front. Useless elements get removed from the back.

Pattern 6: BFS with Queue

Recognize it: Shortest path in unweighted graph. Level-order traversal. Spreading (like rot, fire, infection). "Minimum steps to reach..."

Core idea: Start with initial states in the queue. For each state, generate next states and push to queue if not visited. The first time you reach a target, that's the minimum distance.

Pattern 7: Stack-Based Greedy

Recognize it: Remove elements to get the lexicographically smallest result, or remove k elements to maximize something.

Core idea: Greedily build the answer using a stack. When adding a new element, remove elements from the stack that are worse than the current element (if you still have budget to remove).

Pattern 8: Prefix/Suffix with Stack

Recognize it: You need to precompute information about "what is to the left/right of each element" — like previous smaller element arrays used in range queries.

Core idea: Run the monotonic stack twice — once left-to-right and once right-to-left — to build prefix and suffix arrays, then combine.

03 C++ — Everything You Need

Stack — std::stack

#include <stack>
#include <iostream>
using namespace std;

int main() {
    stack<int> st;

    st.push(10);   // push to top
    st.push(20);
    st.push(30);

    cout << st.top();  // 30 — peek top without removing
    st.pop();         // remove top (returns void!)
    cout << st.top();  // 20 now
    cout << st.size(); // 2
    cout << st.empty(); // false

    // CRITICAL: Always check empty() before top() or pop()
    while (!st.empty()) {
        cout << st.top() << " ";
        st.pop();
    }
    return 0;
}
⚠ Common Bug

pop() in C++ returns void. You cannot do int x = st.pop(). You must do int x = st.top(); st.pop(); to get the value and remove it. This trips up almost everyone.
